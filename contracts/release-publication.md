# Application release publication contract (v4)

This is the CI contract for application installers published from `YaomuStudio/YaomuStudio`. The official download source and the domestic app update feed are an OBS-compatible object store; GitHub Releases remain the build archive and the international update feed. It replaces the Windows-only draft/evidence/approval gate. It is not a model ReleaseManifest, signing-key provisioner, or authorization to publish. Tag creation and public release remain separate owner actions.

## Release identity

- Accept only existing `vMAJOR.MINOR.PATCH` or `vMAJOR.MINOR.PATCH-beta.N` tags with canonical nonnegative integers (no leading zero except `0`). Reject whitespace, shell metacharacters, and non-canonical numbers.
- Resolve the tag to its full 40-hex commit. Root, `ui/package.json`, and `desktop/package.json` versions at that commit must all equal the tag version (with `v` removed).
- Checkout every build and publish job at that exact commit. Do not build from a branch head.
- Stable tags publish as normal releases; `-beta.N` tags publish as GitHub prereleases.

## Trigger and publication

- Automatic builds run only on `push` of a `v*` tag.
- `workflow_dispatch` is a manual rerun/repair path and requires an existing tag; it does not accept branches.
- A tag push builds the current platform matrix: Windows and Linux. macOS builds are temporarily excluded until macOS packaging is fixed and models are ready. Only after every configured build succeeds does the publish job upload immutable artifacts to OBS, create the GitHub Release archive, and finally switch the OBS update manifests. A failed build publishes nothing.
- The release is public by default. There is no draft/approval step in this contract.
- If a release with the same tag already exists, the publish job fails closed. It must not delete, overwrite, or `--clobber` it. Recovering a partially uploaded release is a manual owner action.
- OBS is the official website's only download source and the domestic `electron-updater` feed. GitHub Releases are the international update feed and the build archive, and remain the transition feed for clients built before the switch.

## Build matrix

| Job | Runner | Target |
|---|---|---|
| `build-windows` | `windows-latest` | NSIS, x64 |
| ~~`build-macos`~~ | — | Temporarily excluded; restore DMG + zip (arm64/x64) after macOS packaging is fixed and models are ready. |
| `build-linux` | `ubuntu-24.04` | AppImage, x64 |

- Build jobs use `--publish never`. Only the publish job uploads assets.
- When macOS is re-enabled, it builds both architectures in one invocation so `latest-mac.yml` contains both architectures. Building each architecture separately and uploading two manifests is not allowed.
- `extraResources` selects `desktop/build/core-${arch}` so Core, Python, and FFmpeg match the target architecture.

## Assets

Exact expected asset set for version `V`. The macOS block is not required while macOS release builds are temporarily excluded; it is retained for re-enable.

```text
YaoMuStudio-V-win-x64.exe
YaoMuStudio-V-win-x64.exe.blockmap
latest.yml

YaoMuStudio-V-mac-arm64.dmg
YaoMuStudio-V-mac-arm64.dmg.blockmap
YaoMuStudio-V-mac-arm64.zip
YaoMuStudio-V-mac-arm64.zip.blockmap
YaoMuStudio-V-mac-x64.dmg
YaoMuStudio-V-mac-x64.dmg.blockmap
YaoMuStudio-V-mac-x64.zip
YaoMuStudio-V-mac-x64.zip.blockmap
latest-mac.yml

YaoMuStudio-V-linux-x64.AppImage
YaoMuStudio-V-linux-x64.AppImage.blockmap   # optional if electron-builder emits it
latest-linux.yml
```

- No extra executables, checksum files, source archives, or third-party notices are uploaded as separate assets. License/source notices remain inside the installers.
- `artifactName` is configured in `desktop/electron-builder.yml`; local names and remote names must match.
- `latest*.yml` is generated by electron-builder. Do not hand-edit or invent manifests.
- `latest.json` is generated by the OBS publish script for the official website and is uploaded only to OBS, not to the GitHub Release.

## OBS distribution (canonical)

- Object storage: OBS-compatible object storage, addressed by `OBS_ENDPOINT`, `OBS_BUCKET`, and optional `OBS_PREFIX`.
- Public feed base: `OBS_FEED_BASE_URL`, HTTPS with a trailing slash, mapping one-to-one to the object prefix. It must equal `publish.url` in `desktop/electron-builder.yml`.
- Layout: every installer and blockmap keeps its versioned filename at the feed base; `latest.yml`, `latest-mac.yml`, and `latest-linux.yml` are fixed keys overwritten each release; `latest.json` is a website pointer generated by the publish script.
- Installers are immutable. The publish script skips an existing object only when size and ETag/MD5 match; a same-key object with different bytes fails closed.
- Publish order: verify local assets → upload non-manifest artifacts → verify remote sizes → create and upload the GitHub Release archive → upload `latest*.yml` → upload `latest.json` → verify public bytes/sizes. Manifests are the switch point; never publish them before artifacts and the GitHub archive succeed.
- Cache policy: installers and blockmaps use `public, max-age=31536000, immutable`; manifests and `latest.json` use `no-cache`. `electron-updater` adds a `noCache` query to generic feed requests; the CDN must still honor `no-cache`.
- Public read: every feed object must be anonymously readable over HTTPS (public bucket/prefix or CDN origin). The publish step verifies the public URL; a failure fails the release job.
- `latest.json` schema: `{schema:1, version, published_at, feed, platforms:{win|linux|mac-*:{url,size,sha512}}}`. It does not replace `latest*.yml`; the official website uses it to render fixed download links.
- Old versioned objects are not deleted by the publish job. Retention/cleanup is an operations decision and must not remove a file referenced by the current manifests.

## Verification before publication

The publish job downloads all build artifacts into one directory and runs `scripts/verify-release-assets.mjs`. While macOS is excluded it runs once with `--platform win,linux`, which validates the merged directory against the union of both platforms' expected assets; when macOS is re-enabled, use `--platform win,mac,linux` (or `--platform all`).

1. Reject unknown or non-regular files.
2. Require every expected asset.
3. Parse `latest.yml`, `latest-mac.yml`, and `latest-linux.yml` with the trusted YAML parser.
4. For every `files[]` entry: require a safe basename, positive size, nonempty SHA-512, an existing local file, matching size, and matching base64 SHA-512.
5. Require the Windows installer in `latest.yml` and the Linux AppImage in `latest-linux.yml`. When macOS is enabled, also require both macOS architectures in `latest-mac.yml`.
6. When macOS is enabled, require `latest-mac.yml` to contain both `mac-arm64` and `mac-x64` entries.

The build jobs also verify the generated `app-update.yml` uses the generic provider and matches `publish.url` in `desktop/electron-builder.yml`, and that the packaged Core/Runner/Python/FFmpeg files exist. The OBS publish steps additionally HEAD every artifact through the public feed URL and GET every manifest/`latest.json` to compare exact bytes.

Artifacts are consumed from the same workflow run's artifact store. This contract does not add a separate signed provenance channel beyond the workflow run identity and the asset hashes.

## Signing and platform policy

- Windows builds may be unsigned. Unsigned installers can be distributed, but SmartScreen may warn. The release notes must say so.
- macOS release builds are temporarily excluded until macOS packaging is fixed and models are ready. When re-enabled, they are unsigned previews: Gatekeeper requires right-click → Open and auto-update is unavailable.
- Linux AppImage builds are unsigned previews. Auto-update is not verified on a real desktop.
- Model execution is Windows + WSL2 by default. Linux host execution is best-effort. macOS builds and model execution are not part of the current release. Release notes must state this.
- Do not claim a signature, notarization, or auto-update capability that the build did not produce.

## Release notes

Use `gh release create --generate-notes` plus a short prepended note:

```text
> 未签名构建：Windows 可能触发 SmartScreen。
> Linux 为 preview；模型执行以 Windows + WSL2 为基线，Linux 为 best-effort。
> macOS 发布构建暂时排除，等打包修复且模型就绪后再提供。
```

Beta tags must also pass `--prerelease`.

## Permissions and secrets

- Build jobs: `contents: read`.
- Publish job: `contents: write` for the GitHub archive, using `secrets.GITHUB_TOKEN`.
- OBS repository variables: `OBS_ENDPOINT`, `OBS_BUCKET`, `OBS_PREFIX` (optional), `OBS_FEED_BASE_URL`.
- OBS secrets: `OBS_ACCESS_KEY_ID`, `OBS_SECRET_ACCESS_KEY`; optional `OBS_SECURITY_TOKEN` for temporary credentials.
- The OBS IAM identity must only allow `PutObject`, `GetObject`, and `HeadObject` on the release bucket/prefix, not bucket administration. The bucket/prefix is anonymously readable over HTTPS; the feed contains no credentials.
- Windows signing, if configured, reads `WIN_CSC_LINK` and `WIN_CSC_KEY_PASSWORD` from secrets. Missing secrets produce an unsigned build; they do not block the pipeline.
- No long-lived PAT, no cross-repository token, and no credentials in client binaries or release assets.
- Logs must not print tokens, full environment variables, or private key material. The publish script must not echo `OBS_ACCESS_KEY_ID` or `OBS_SECRET_ACCESS_KEY`.

## Failure and race semantics

- A failed build prevents release creation and OBS manifest publication.
- A failed local verification prevents any OBS or GitHub publication.
- A failed OBS artifact upload or public verification prevents GitHub Release creation and manifest publication.
- A failed GitHub Release creation or asset upload prevents OBS manifest publication; the new OBS artifacts stay dormant because the previous manifests remain live.
- Artifact upload and manifest publication are separate API calls. A partial OBS manifest switch (for example Windows manifest uploaded, Linux manifest failed) is not atomic; the job must fail and the owner must restore the previous manifest manually.
- Release creation and asset upload are separate GitHub API calls; this contract does not claim atomic publication. If creation succeeds and upload fails, the release may be visible with incomplete assets. The job must fail and the owner must fix it manually; a rerun refuses to touch the existing release.
- GitHub users or other systems can mutate a release after publication. This contract does not claim an atomic compare-and-swap over the release.

## Relationship to app updates

- `desktop/electron-builder.yml` sets the default generic feed to OBS (`latest.yml`, `latest-mac.yml`, `latest-linux.yml`). `desktop/src/update-feed.ts` selects OBS for Simplified Chinese locales or China time zones and GitHub for other locales, and falls back to the other feed once when a check fails.
- The official website's download links resolve the current version through `latest.json`; the site must not hard-code a fixed installer filename.
- Windows NSIS is the primary auto-update path. macOS unsigned previews do not support auto-update. Linux AppImage update behavior is unverified.
- The app never embeds OBS or GitHub credentials; both feeds are anonymous.
- Migration: clients built before the switch still read GitHub Releases. Keep publishing GitHub Releases until those clients have moved to the dual-feed version; the first dual-feed release must therefore also be published to GitHub.

## Retired mechanism

The previous Windows-only `resolve/build/stage/verify/publish` draft gate, `release-build-evidence.json`, `RELEASE_APPROVED_*` repository variables, and Authenticode evidence channel are retired by this contract. They must not be reintroduced into the tag pipeline without a new contract revision.

## Verification boundary

Static workflow tests, asset verification on locally built macOS artifacts, and unit tests do not prove a real Windows/Linux CI run, a real GitHub Release, a real OBS upload/public feed, or a real `electron-updater` upgrade. Those remain unverified until executed on the public repository with configured OBS credentials and a public feed URL.
